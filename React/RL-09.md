## 📘 Lesson 13: React Performance Optimization – `React.memo`, `useMemo`, and `useCallback`

---

### 🧩 Part 1: The Re-render Problem

#### 🔍 Problem:

> In React, every time a **state or prop changes**, the component **re-renders** — even its children, *unless optimized*.

This can lead to:

* Slower performance
* Unnecessary re-renders
* Wasted memory/computation

---

### 🧩 Part 2: `React.memo` – Prevent Child Re-renders

#### ✅ What It Does:

> `React.memo()` **wraps a component** and tells React:
> ➤ "Only re-render this if props actually change."

---

### ✨ Example:

```jsx
const Child = React.memo(function Child({ name }) {
  console.log('Child rendered');
  return <p>Hello, {name}</p>;
});
```

#### Parent:

```jsx
function Parent() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <Child name="Tushar" />
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}
```

✅ Now clicking the button won’t re-render `<Child />` if `name` hasn't changed.

---

### 🧠 `React.memo()` Recap

| Use When                                          | Result              |
| ------------------------------------------------- | ------------------- |
| Child is **pure** and receives same props often   | Prevents re-renders |
| Performance critical rendering                    | Improves speed      |
| Props are **primitive** (string, number, boolean) | Memo works well     |

---

### 🧩 Part 3: `useCallback` – Memoize Functions

#### 🔍 Problem:

Passing functions as props creates **new function instances** every render.

✅ `useCallback` returns the **same function** reference unless its dependencies change.

---

### ✅ Syntax

```jsx
const memoizedCallback = useCallback(() => {
  doSomething(a, b);
}, [a, b]);
```

---

### ✨ Example:

```jsx
const handleClick = useCallback(() => {
  console.log('Clicked!');
}, []);
```

---

### 🔁 When to Use `useCallback`?

| Use Case                           | Why                            |
| ---------------------------------- | ------------------------------ |
| Passing function to memoized child | Prevent unnecessary re-renders |
| Expensive callbacks                | Save function reference        |
| Inline functions inside components | Avoid recreation               |

---

### 🧩 Part 4: `useMemo` – Memoize Expensive Calculations

#### 🔍 Problem:

Sometimes functions do **heavy work** (loops, math, filters) **on every render**.

✅ `useMemo` **caches** the return value of a function unless its dependencies change.

---

### ✅ Syntax

```jsx
const result = useMemo(() => expensiveOperation(input), [input]);
```

---

### ✨ Example:

```jsx
const squared = useMemo(() => {
  console.log('Calculating square');
  return number * number;
}, [number]);
```

✅ It avoids recalculating unless `number` changes.

---

### 🧠 Summary Table

| Tool          | Purpose                                  |
| ------------- | ---------------------------------------- |
| `React.memo`  | Avoid re-render of pure child components |
| `useCallback` | Memoize functions                        |
| `useMemo`     | Memoize expensive values                 |

### ❗ Common Mistakes to Avoid

| Mistake                                     | Fix                                                    |
| ------------------------------------------- | ------------------------------------------------------ |
| Overusing `useMemo`/`useCallback`           | Use only when **actual performance issues** exist      |
| Passing non-primitive props to `React.memo` | Use shallow comparison or convert objects to primitive |
| Not wrapping child in `React.memo`          | Function props still cause re-renders                  |

---

### 📌 Rule of Thumb

> Optimize **only if**:

* Component re-renders unnecessarily
* You notice UI lag
* Expensive calculations are involved
