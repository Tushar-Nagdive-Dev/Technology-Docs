## 📘 Lesson 19: Global State Management with Redux Toolkit and Zustand

---

### 🧩 Why Global State Libraries?

> As your app grows, **lifting state up** or using `Context` alone becomes **unmanageable** for:

* Auth state
* Notifications
* Shopping carts
* Admin panels
* Reusable business logic

---

## 🛠 Option 1: Redux Toolkit (Recommended Redux Approach)

---

### ✅ Step 1: Install Redux Toolkit

```bash
npm install @reduxjs/toolkit react-redux
```

---

### 📁 Suggested Folder Structure

```
src/
├── app/
│   └── store.js
├── features/
│   └── user/
│       ├── userSlice.js
├── App.jsx
```

---

### ✅ Step 2: Configure Store

📄 `app/store.js`

```jsx
import { configureStore } from '@reduxjs/toolkit';
import userReducer from '../features/user/userSlice';

export const store = configureStore({
  reducer: {
    user: userReducer
  }
});
```

---

### ✅ Step 3: Create a Slice

📄 `features/user/userSlice.js`

```jsx
import { createSlice } from '@reduxjs/toolkit';

const initialState = {
  name: '',
  loggedIn: false
};

const userSlice = createSlice({
  name: 'user',
  initialState,
  reducers: {
    login(state, action) {
      state.name = action.payload;
      state.loggedIn = true;
    },
    logout(state) {
      state.name = '';
      state.loggedIn = false;
    }
  }
});

export const { login, logout } = userSlice.actions;
export default userSlice.reducer;
```

---

### ✅ Step 4: Wrap App with Provider

📄 `main.jsx`

```jsx
import { Provider } from 'react-redux';
import { store } from './app/store';

ReactDOM.createRoot(document.getElementById('root')).render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

---

### ✅ Step 5: Use Redux State in Components

```jsx
import { useSelector, useDispatch } from 'react-redux';
import { login, logout } from './features/user/userSlice';

function UserProfile() {
  const user = useSelector((state) => state.user);
  const dispatch = useDispatch();

  return (
    <div>
      <h2>{user.loggedIn ? `👋 Welcome, ${user.name}` : 'Please log in'}</h2>
      {user.loggedIn ? (
        <button onClick={() => dispatch(logout())}>Logout</button>
      ) : (
        <button onClick={() => dispatch(login('Tushar'))}>Login</button>
      )}
    </div>
  );
}
```

---

## ✅ When to Use Redux Toolkit?

| When                                 | Why                        |
| ------------------------------------ | -------------------------- |
| You have many shared states          | Centralizes them           |
| You need predictable, testable state | Uses reducers & actions    |
| You want to integrate devtools       | Comes built-in             |
| You prefer opinionated structure     | RTK simplifies Redux setup |

---

## 🟡 Optional: Redux DevTools

Redux Toolkit integrates automatically with DevTools. Just install the browser extension.

## 🛠 Option 2: Zustand – Minimal & Fast Alternative

---

### ✅ Step 1: Install Zustand

```bash
npm install zustand
```

---

### ✅ Step 2: Create Store

📄 `store/useUserStore.js`

```jsx
import { create } from 'zustand';

const useUserStore = create((set) => ({
  name: '',
  loggedIn: false,
  login: (name) => set({ name, loggedIn: true }),
  logout: () => set({ name: '', loggedIn: false })
}));

export default useUserStore;
```

---

### ✅ Step 3: Use Zustand Store in Components

```jsx
import useUserStore from './store/useUserStore';

function UserProfile() {
  const { name, loggedIn, login, logout } = useUserStore();

  return (
    <div>
      <h2>{loggedIn ? `Welcome, ${name}` : 'Please log in'}</h2>
      {loggedIn ? (
        <button onClick={logout}>Logout</button>
      ) : (
        <button onClick={() => login('Tushar')}>Login</button>
      )}
    </div>
  );
}
```

✅ No boilerplate. No provider needed. Zustand is perfect for small to mid-sized apps.

---

## ⚔️ Redux Toolkit vs Zustand

| Feature           | Redux Toolkit            | Zustand          |
| ----------------- | ------------------------ | ---------------- |
| Boilerplate       | More (actions, reducers) | Minimal setup    |
| Built-in DevTools | ✅                        | ✅ via middleware |
| TypeScript Ready  | ✅                        | ✅                |
| App Size          | Medium to Large          | Small to Medium  |
| Custom logic      | With Thunks, Middleware  | Inline methods   |
