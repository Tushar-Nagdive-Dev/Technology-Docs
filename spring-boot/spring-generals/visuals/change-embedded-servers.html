Spring Boot: Embedded Servers Guide

1 Available Servers & Advantages

Spring Boot supports three main embedded servers for standard web applications (Servlet stack), plus one for reactive applications.

1. Apache Tomcat (The Default)

What it is: The undisputed heavyweight champion of Java web servers. It is the default server that comes automatically when you add spring-boot-starter-web.

Advantages: Massive community support, heavily battle-tested in enterprise environments, standard thread-per-request model, and incredibly stable.

2. Eclipse Jetty

What it is: A highly scalable, memory-efficient alternative to Tomcat.

Advantages: Very lightweight footprint, excellent for handling thousands of concurrent connections using minimal memory, fast startup time. Often favored in cloud environments.

3. Undertow (by Red Hat / JBoss)

What it is: A highly flexible, high-performance web server written in Java.

Advantages: Lightning-fast throughput and blocking/non-blocking I/O support. It is known for having the best raw performance and lowest latency among the big three for standard REST APIs.

4. Netty (For WebFlux)

What it is: An asynchronous, event-driven network application framework.

Advantages: Not a standard "Servlet" container like the others. It is the default for Spring WebFlux (Reactive programming) designed to handle massive concurrency without blocking threads.

2 When to Use Which Server?

  • Use Tomcat if: You want a "plug-and-play" experience with zero configuration, maximum compatibility with legacy libraries, and the easiest time finding Stack Overflow answers when things go wrong. (Standard choice for 80% of apps).
  • Use Jetty if: You are deploying microservices to memory-constrained environments (like cheap AWS/Azure instances or Kubernetes pods) where saving 50MB of RAM per instance matters. Also great for IoT devices.
  • Use Undertow if: You need absolute maximum throughput and speed for heavy I/O operations. If you are building a high-traffic API gateway or processing massive volumes of requests, Undertow's architecture shines.
  • Use Netty if: You are building a purely Reactive application using spring-boot-starter-webflux.

4 Process & Code to Change the Server

The Process in Simple Terms:

  1. Spring Boot auto-configures Tomcat because it is bundled inside the spring-boot-starter-web dependency.
  2. To change it, you must tell your build tool (Maven or Gradle) to exclude Tomcat from the starter-web package.
  3. Then, you explicitly include the starter for the server you want (e.g., spring-boot-starter-undertow).

Example: Changing from Tomcat to Undertow (Maven)

Open your pom.xml file and update your web dependency:

<dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-web</artifactId> <!-- 1. Exclude Tomcat --> <exclusions> <exclusion> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-tomcat</artifactId> </exclusion> </exclusions> </dependency> <!-- 2. Include Undertow (or Jetty) --> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-undertow</artifactId> </dependency>

Example: Changing from Tomcat to Jetty (Gradle)

Open your build.gradle file and update your dependencies block:

dependencies { // 1. Include web starter, but exclude Tomcat implementation("org.springframework.boot:spring-boot-starter-web") { exclude module: "spring-boot-starter-tomcat" } // 2. Include Jetty implementation("org.springframework.boot:spring-boot-starter-jetty") }

Note: For Spring Boot 3+ (which uses Jakarta EE), this exact same process applies. Just restart your application, and you will see the new server name pop up in your console logs!
