The Deserialization Journey

How Spring Boot turns JSON into Java Objects

1

The Request Arrives (DispatcherServlet)

When a client sends a POST request with a JSON body, it first hits the DispatcherServlet (the Front Controller). The servlet looks at the URL and determines which Controller method should handle this request. It delegates the execution to the RequestMappingHandlerAdapter.

2

Spotting the @RequestBody Annotation

The Handler Adapter inspects your controller method's signature. It sees the @RequestBody annotation next to your parameter (e.g., UserDTO user).

This annotation acts as a flag. It tells Spring: "Do not try to map this from URL parameters or form data. The data is entirely inside the raw HTTP Request Body."

@PostMapping("/users") public ResponseEntity<String> createUser(@RequestBody UserDTO user) { // How did 'user' get here? }
3

The HttpMessageConverter Loop

Spring Boot does not parse JSON itself. It relies on an interface called HttpMessageConverter. When you include spring-boot-starter-web, Spring automatically registers several of these converters in the background (for JSON, XML, String, Byte Arrays, etc.).

Spring iterates through its list of registered converters and asks two questions:

  • Does this converter support the Content-Type of the request? (The client sent application/json).
  • Can this converter read the target Java class? (UserDTO.class).

The MappingJackson2HttpMessageConverter steps up and says, "I can do both!"

4

Jackson's ObjectMapper Takes Over

The MappingJackson2HttpMessageConverter is essentially a wrapper around the famous Jackson library. It passes the raw InputStream of the HTTP Request to Jackson's core class: the ObjectMapper.

The ObjectMapper is the true workhorse. It reads the JSON string and begins the process of converting it to your UserDTO.

5

Java Reflection & Instantiation (The Deep Magic)

Here is exactly how Jackson builds your object piece by piece:

  1. Instantiation: Jackson uses Java Reflection to look at UserDTO.class. By default, it looks for a No-Arguments Constructor. It calls this constructor to create an empty, shell object in memory.
  2. Field Matching: It reads the first JSON key (e.g., "firstName": "John"). It uses Reflection to look for a corresponding field or a Setter method in the Java class (e.g., setFirstName("John")).
  3. Type Conversion: If the JSON value is a string "25", but the Java field is an Integer age, Jackson automatically converts the string to an Integer.
  4. Population: It injects the values into the empty object, fully hydrating it.

Once Jackson finishes, it hands the fully populated UserDTO back to Spring, which then passes it as the argument into your Controller method.

🔍 The "Minute Details" (What Seniors Know)

1. What if there is no default constructor?
If your Java class only has an all-arguments constructor (like a Java Record or when using Lombok's @AllArgsConstructor without @NoArgsConstructor), Jackson will throw an exception. Fix: You must configure Jackson to use the ParameterNames module, or add @JsonCreator to the constructor, or simply provide a no-args constructor.

2. Getters/Setters vs. Field Access:
Jackson prefers using public Setters to populate data. However, if you don't have Setters (for immutability), Jackson can use Field-level reflection to inject values directly into private fields if configured to do so, though it is slightly slower.

3. Naming Strategy Mismatches:
If your JSON sends first_name but your Java variable is firstName, Jackson will ignore it and leave the field null.
Fix: You add @JsonProperty("first_name") to the Java field, or configure a global PropertyNamingStrategy.SNAKE_CASE in your application.yml.

4. Unknown Properties:
If the JSON contains a field (e.g., "middleName": "Lee") that does NOT exist in your Java class, Jackson will throw an UnrecognizedPropertyException by default.
Fix: Add @JsonIgnoreProperties(ignoreUnknown = true) to the top of your class.

5. When does Validation (@Valid) happen?
If you have @Valid @RequestBody UserDTO user, the validation happens AFTER Jackson successfully builds the object, but BEFORE your controller method executes. If the object fails validation, Spring throws a MethodArgumentNotValidException and your method never even runs.
