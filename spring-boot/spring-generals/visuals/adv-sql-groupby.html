Advanced SQL GROUP BY: Rollup, Cube & Grouping Sets

The Scenario: Imagine you are a Data Analyst for a retail company. You have a table called Sales_Data that records sales across different Regions and Categories.

Standard GROUP BY only gives you the final aggregates. But your manager wants to see Subtotals and Grand Totals in a single query result. Here is our starting data:

Base Table: Sales_Data

RegionCategorySales_Amount
NorthElectronics1000
NorthClothing500
SouthElectronics800
SouthClothing600

1. ROLLUP(): The "Hierarchical Subtotal" Maker

Simple Terms: ROLLUP is perfect for financial reports. It creates subtotals moving from right to left across your group columns, plus a final Grand Total at the very bottom. If you ROLLUP (Region, Category), it gives you: Detail Level + Region Subtotals + Grand Total.

SELECT Region, Category, SUM(Sales_Amount) AS Total_Sales
FROM Sales_Data
GROUP BY ROLLUP(Region, Category);

2. CUBE(): The "All Possible Combinations" Maker

Simple Terms: CUBE does everything ROLLUP does, but it also generates subtotals for every possible combination of the columns. Not only do you get Region subtotals, but you also get Category subtotals! It’s like generating a pivot table cross-tabulation in one query.

SELECT Region, Category, SUM(Sales_Amount) AS Total_Sales
FROM Sales_Data
GROUP BY CUBE(Region, Category);

3. GROUPING SETS(): The "A La Carte" Menu

Simple Terms: What if you only want the Region subtotals and the Category subtotals, but you don't care about the detail rows or the Grand Total? CUBE generates too much data. GROUPING SETS lets you explicitly pick exactly which groupings you want to calculate.

SELECT Region, Category, SUM(Sales_Amount) AS Total_Sales
FROM Sales_Data
GROUP BY GROUPING SETS ( (Region), (Category) );
RegionCategoryTotal_SalesExplanation
NorthNULL1500Grouped strictly by Region
SouthNULL1400Grouped strictly by Region
NULLElectronics1800Grouped strictly by Category
NULLClothing1100Grouped strictly by Category

Notice there are no detail rows (Region + Category combined) and no Grand Total, because we didn't ask for them in the sets!

4. The GROUPING() Function: Fixing the "NULL" Confusion

Simple Terms: When using ROLLUP or CUBE, the subtotals show up with a NULL value in the columns. But what if your raw data actually contains a real NULL region? How do you tell the difference between an empty Region and a "Total" row?

The GROUPING() function returns a 1 if the NULL was generated by ROLLUP/CUBE as a subtotal, and a 0 if it's actual raw data.

SELECT
    CASE WHEN GROUPING(Region) = 1 THEN 'ALL REGIONS' ELSE Region END AS Region,
    CASE WHEN GROUPING(Category) = 1 THEN 'ALL CATEGORIES' ELSE Category END AS Category,
    SUM(Sales_Amount) AS Total_Sales
FROM Sales_Data
GROUP BY ROLLUP(Region, Category);
