Model Context Protocol (MCP) Server

End-to-End Implementation Guide for Java & Spring Boot

1. Introduction to MCP

The Model Context Protocol (MCP) is an open standard introduced to standardize how AI models (like Claude) connect to external data sources, tools, and prompts. Instead of writing custom API integrations for every AI client, you write one MCP Server, and any MCP-compliant client can instantly understand your tools and data.

Core Capabilities of an MCP Server:
  • Resources: Expose raw data or files (e.g., reading a local log file, querying a database schema).
  • Tools: Executable functions the AI can call to take action (e.g., executing a SQL query, triggering a build).
  • Prompts: Reusable prompt templates exposed to the client.

2. Architecture & Transport Layer

MCP operates over JSON-RPC 2.0. In a Java/Spring Boot context, you generally implement one of two Transport layers:

  1. Standard I/O (stdio): The AI Client runs your Spring Boot app as a subprocess. It communicates by writing JSON to System.in and reading from System.out. (Most common for desktop integrations like Claude Desktop).
  2. Server-Sent Events (SSE) / HTTP: The server runs as a standard REST API. The client connects via SSE for server-to-client messages and standard HTTP POST for client-to-server.

This guide focuses on the StdIO transport embedded inside a Spring Boot CLI app, as it is the most strict and requires careful handling of Java's logging.

3. Minute Details: The "Gotchas" of Java MCP

CRITICAL LOGGING RULE: When using the StdIO transport, your application MUST NOT write any raw text (like Spring Boot startup banners or SLF4J logs) to System.out. The client expects strictly valid JSON-RPC payloads on System.out. Any standard logging must be redirected to System.err or a file.

4. Spring Boot Project Setup

Create a standard Spring Boot project (Java 17+) using Maven or Gradle. Add Jackson for JSON processing.

pom.xml Dependencies

<dependencies>
    <!-- Spring Boot Starter -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter</artifactId>
    </dependency>

    <!-- Jackson for JSON-RPC Parsing -->
    <dependency>
        <groupId>com.fasterxml.jackson.core</groupId>
        <artifactId>jackson-databind</artifactId>
    </dependency>

    <!-- Optional: Lombok for boilerplate -->
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>
</dependencies>

Application.properties Setup

Turn off the Spring Boot banner and redirect logs to stderr to prevent corrupting the JSON-RPC stream.

spring.main.banner-mode=off
logging.pattern.console=%d{yyyy-MM-dd HH:mm:ss} - %msg%n
# Redirect all console logs to standard error
logging.console.out=system.err

5. The E2E Code Implementation

Step 5.1: JSON-RPC Model Classes

Create the base classes for the MCP JSON-RPC protocol.

package com.example.mcp.model;

import com.fasterxml.jackson.annotation.JsonInclude;
import com.fasterxml.jackson.databind.JsonNode;
import lombok.Data;

@Data
@JsonInclude(JsonInclude.Include.NON_NULL)
public class JsonRpcMessage {
    private String jsonrpc = "2.0";
    private Object id;       // Can be String or Integer
    private String method;
    private JsonNode params; // For requests
    private JsonNode result; // For responses
    private JsonNode error;  // For errors
}

Step 5.2: The Core Transport / Loop (Spring Component)

We need a CommandLineRunner that continuously reads from System.in, parses the request, processes it, and writes the JSON response to System.out.

package com.example.mcp.transport;

import com.example.mcp.model.JsonRpcMessage;
import com.example.mcp.service.McpDispatcher;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.nio.charset.StandardCharsets;

@Component
public class StdioMcpServer implements CommandLineRunner {

    private final ObjectMapper mapper;
    private final McpDispatcher dispatcher;

    public StdioMcpServer(ObjectMapper mapper, McpDispatcher dispatcher) {
        this.mapper = mapper;
        this.dispatcher = dispatcher;
    }

    @Override
    public void run(String... args) throws Exception {
        BufferedReader reader = new BufferedReader(new InputStreamReader(System.in, StandardCharsets.UTF_8));
        String line;
        
        // Endless loop to read from AI Client
        while ((line = reader.readLine()) != null) {
            try {
                if (line.trim().isEmpty()) continue;
                
                // 1. Parse Input
                JsonRpcMessage request = mapper.readValue(line, JsonRpcMessage.class);
                
                // 2. Dispatch to Handlers
                JsonRpcMessage response = dispatcher.handle(request);
                
                // 3. Write Output directly to System.out
                if (response != null) {
                    System.out.println(mapper.writeValueAsString(response));
                    System.out.flush(); // CRITICAL: Must flush so client receives it
                }
            } catch (Exception e) {
                // Log to System.err, NEVER System.out
                System.err.println("Error processing message: " + e.getMessage());
            }
        }
    }
}

Step 5.3: The MCP Dispatcher & Protocol Handlers

The Dispatcher routes the JSON-RPC methods (initialize, tools/list, tools/call) to your Spring Services.

package com.example.mcp.service;

import com.example.mcp.model.JsonRpcMessage;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.node.ObjectNode;
import org.springframework.stereotype.Service;

@Service
public class McpDispatcher {

    private final ObjectMapper mapper;
    private final ToolService toolService;

    public McpDispatcher(ObjectMapper mapper, ToolService toolService) {
        this.mapper = mapper;
        this.toolService = toolService;
    }

    public JsonRpcMessage handle(JsonRpcMessage request) {
        JsonRpcMessage response = new JsonRpcMessage();
        response.setId(request.getId()); // Match ID for synchronous response

        String method = request.getMethod();
        if (method == null) return null; // Notifications don't require response

        switch (method) {
            case "initialize":
                response.setResult(handleInitialize());
                break;
            case "tools/list":
                response.setResult(toolService.listTools());
                break;
            case "tools/call":
                response.setResult(toolService.callTool(request.getParams()));
                break;
            // Add resources/list, prompts/list here...
            default:
                // Method not found
                ObjectNode error = mapper.createObjectNode();
                error.put("code", -32601);
                error.put("message", "Method not found");
                response.setError(error);
        }
        return response;
    }

    private ObjectNode handleInitialize() {
        // Required MCP initialization handshake
        ObjectNode result = mapper.createObjectNode();
        result.put("protocolVersion", "2024-11-05");
        
        ObjectNode serverInfo = result.putObject("serverInfo");
        serverInfo.put("name", "spring-boot-mcp-server");
        serverInfo.put("version", "1.0.0");
        
        ObjectNode capabilities = result.putObject("capabilities");
        capabilities.putObject("tools"); // Declare we support tools
        // capabilities.putObject("resources"); // If supported
        
        return result;
    }
}

Step 5.4: Implementing the Tools (The actual Logic)

This is where your Spring Boot logic lives. We describe a tool schema (using JSON Schema) so the AI knows how to call it, and we execute it when called.

package com.example.mcp.service;

import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.node.ArrayNode;
import com.fasterxml.jackson.databind.node.ObjectNode;
import org.springframework.stereotype.Service;

@Service
public class ToolService {

    private final ObjectMapper mapper;

    public ToolService(ObjectMapper mapper) {
        this.mapper = mapper;
    }

    public JsonNode listTools() {
        ObjectNode result = mapper.createObjectNode();
        ArrayNode tools = result.putArray("tools");

        // Define a "get_weather" tool
        ObjectNode weatherTool = tools.addObject();
        weatherTool.put("name", "get_weather");
        weatherTool.put("description", "Get the current weather for a specific city.");
        
        // Define JSON Schema for inputs
        ObjectNode inputSchema = weatherTool.putObject("inputSchema");
        inputSchema.put("type", "object");
        ObjectNode properties = inputSchema.putObject("properties");
        
        ObjectNode location = properties.putObject("location");
        location.put("type", "string");
        location.put("description", "The city name, e.g., San Francisco");
        
        ArrayNode required = inputSchema.putArray("required");
        required.add("location");

        return result;
    }

    public JsonNode callTool(JsonNode params) {
        String toolName = params.get("name").asText();
        JsonNode arguments = params.get("arguments");

        ObjectNode result = mapper.createObjectNode();
        ArrayNode content = result.putArray("content");

        if ("get_weather".equals(toolName)) {
            String location = arguments.has("location") ? arguments.get("location").asText() : "Unknown";
            
            // --- YOUR SPRING SERVICE LOGIC GOES HERE ---
            // Example: String weather = externalWeatherApiService.getWeather(location);
            String mockWeather = "The weather in " + location + " is currently 72°F and sunny.";
            
            ObjectNode textContent = content.addObject();
            textContent.put("type", "text");
            textContent.put("text", mockWeather);
        } else {
            result.put("isError", true);
            ObjectNode errorContent = content.addObject();
            errorContent.put("type", "text");
            errorContent.put("text", "Unknown tool: " + toolName);
        }

        return result;
    }
}

6. Compiling and Integration

To use this server with a client (like Claude Desktop), you need to build the Java application into an executable Jar.

Step 6.1: Build the JAR

mvn clean package

This generates target/mcp-server-1.0.jar.

Step 6.2: Configure Claude Desktop

Locate the Claude Desktop configuration file:

  • Mac: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%\Claude\claude_desktop_config.json

Add your Spring Boot server to the config:

{
  "mcpServers": {
    "spring-weather-server": {
      "command": "java",
      "args": [
        "-jar",
        "/absolute/path/to/your/target/mcp-server-1.0.jar"
      ]
    }
  }
}

7. Troubleshooting Minute Details

  • Server fails to start / No Tools showing: 99% of the time, this is caused by standard output pollution. Ensure NO library (Hibernate, Spring, etc.) is printing to System.out. Double check spring.main.banner-mode=off.
  • JSON Parsing Errors: Ensure your JSON responses match the exact schema required by MCP. Use @JsonInclude(JsonInclude.Include.NON_NULL) to avoid sending null properties (like error when there is none), which violates JSON-RPC standard.
  • Statefulness: Remember that in Stdio mode, the Spring context stays alive as long as the subprocess is alive. You can safely inject `@Singleton` beans, cache data, or hold database connections.
  • Ping Method: AI clients frequently send a ping request. If you get a method ping, just return an empty response with the matching ID to keep the connection alive.
Note on Spring AI: The Spring AI framework is actively integrating official MCP support. When using `spring-ai-mcp-server`, much of the boilerplate JSON-RPC dispatcher logic above is abstracted away, allowing you to simply annotate methods with `@Tool`. However, understanding the underlying JSON-RPC Stdio mechanism is essential for debugging and creating E2E reliable integrations in Java.
