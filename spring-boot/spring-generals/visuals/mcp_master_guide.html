01 · Introduction

What is MCP?

Model Context Protocol (MCP) is an open standard by Anthropic that defines how AI models connect to external tools, data sources, and services — in a structured, secure, and reusable way.

Think of MCP the same way you think of USB-C: a universal connector. Before USB-C, every device had its own proprietary charger. Similarly, before MCP, every AI integration was custom-coded from scratch. MCP standardises the plug.

The core idea in one sentence

Key insightAn MCP Server is a lightweight process that exposes capabilities (tools, data, prompts) to an AI model via a standardised protocol, so the model can call those capabilities at runtime — without ever seeing your raw API keys or internal logic.

Real-world analogy

Imagine a restaurant kitchen. You (the user) place an order with the waiter (the AI). The waiter doesn't cook — they carry your request to the kitchen (MCP Server). The kitchen has its own tools, recipes, and ingredients (your database, file system, APIs). The kitchen prepares the dish and hands it back via the waiter.

The waiter never needs to know how to cook. The kitchen never needs to know how the dining room works. The menu (tool definitions) is the contract between them.

02 · Motivation

Why MCP exists

Before MCP, connecting an AI to external tools required brittle, one-off integrations for every AI platform and every tool. MCP solves this with a single protocol.

The "N × M" problem

If you have N different AI models and M different tools, you needed N × M custom integrations. With MCP, you only need N + M — each AI implements MCP once, each tool implements MCP once.

Timeline: how we got here

2022 — Tool calling arrives
OpenAI introduces function calling. Each model has its own schema format, no standard.
2023 — Plugin chaos
Hundreds of custom AI plugins, each needing its own integration per model. Maintenance nightmare.
Nov 2024 — MCP launched
Anthropic open-sources MCP, a universal protocol. SDK for Python, TypeScript, Java, Kotlin, C#.
2025 — Industry adoption
Google, OpenAI, and major cloud providers announce MCP compatibility.
03 · Architecture

Architecture overview

MCP uses a client-server architecture. Three roles exist: Host, Client, and Server. Understanding the difference is the key to understanding MCP.

The three roles

🏠

Host

The application the user runs — Claude Desktop, an IDE plugin, your custom app. It manages MCP clients and exposes them to the AI model.

🔗

Client

Lives inside the Host. Maintains exactly one connection to one MCP Server. Handles protocol translation, capability negotiation.

⚙️

Server

The external process you build. Exposes tools, resources, and prompts. Can be local (stdio) or remote (HTTP/SSE).

04 · Lifecycle

Connection lifecycle

Every MCP connection goes through four phases. Understanding these phases is critical to debugging and building reliable integrations.

Step 1 of 5
1

Initialization

Client sends an initialize request with its protocol version and capabilities.

JSON-RPC Client → Server: initialize 
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2024-11-05",
    "capabilities": {
      "roots": { "listChanged": true },
      "sampling": {}
    },
    "clientInfo": {
      "name": "MyJavaClient",
      "version": "1.0.0"
    }
  }
}
2

Capability exchange

Server responds with its protocol version and what it supports — tools, resources, prompts, logging, etc.

JSON-RPC Server → Client: initialize response 
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2024-11-05",
    "capabilities": {
      "tools": { "listChanged": true },
      "resources": { "subscribe": true },
      "prompts": {},
      "logging": {}
    },
    "serverInfo": {
      "name": "MyJavaServer",
      "version": "1.0.0"
    }
  }
}
3

Initialized notification

Client sends an initialized notification — a fire-and-forget signal that the handshake is complete. No response expected.

JSON-RPC Client → Server: notification (no id!) 
{
  "jsonrpc": "2.0",
  "method": "notifications/initialized"
  // Note: no "id" field — this is a notification, not a request
}

Key distinctionIn MCP, requests have an id field and expect a response. Notifications have no id and are fire-and-forget.

4

Active operation

The connection is live. Client can now call tools, read resources, get prompts, and the server can send back results or push notifications.

JSON-RPC Client → Server: tool call 
{
  "jsonrpc": "2.0",
  "id": 42,
  "method": "tools/call",
  "params": {
    "name": "read_file",
    "arguments": {
      "path": "/home/user/report.txt"
    }
  }
}
5

Shutdown

Either side can close the connection. Graceful shutdown uses the transport's close mechanism (close stdin for stdio, HTTP disconnect for SSE).

ImportantServers must handle abrupt disconnections gracefully. Clean up resources, close database connections, and flush any pending logs on shutdown.

05 · Primitives

Tools, Resources & Prompts

MCP servers expose three types of capabilities, each with a distinct purpose and interaction pattern.

Tools are functions the AI can call. They are model-controlled — the AI decides when to call them based on context. Tools can have side effects (write files, send emails).

JSON Tool definition schema 
{
  "name": "send_email",
  "description": "Send an email to a recipient",
  "inputSchema": {
    "type": "object",
    "properties": {
      "to": { "type": "string", "description": "Recipient email" },
      "subject": { "type": "string" },
      "body": { "type": "string" }
    },
    "required": ["to", "subject", "body"]
  }
}
May have side effects Model-controlled Human approval possible

Resources are data the AI can read. They are application-controlled — the host decides when to expose them. Resources are typically read-only and identified by a URI.

JSON Resource definition 
{
  "uri": "file:///home/user/config.json",
  "name": "App Configuration",
  "description": "Main application configuration file",
  "mimeType": "application/json"
}

// Reading a resource:
{
  "method": "resources/read",
  "params": { "uri": "file:///home/user/config.json" }
}
Read-only (typically) Application-controlled URI-addressed

Prompts are reusable templates that servers can provide to the AI. They are user-controlled — the user explicitly selects which prompt template to use. Think of them as slash commands.

JSON Prompt definition 
{
  "name": "code_review",
  "description": "Review Java code for bugs and style issues",
  "arguments": [
    {
      "name": "code",
      "description": "The Java code to review",
      "required": true
    }
  ]
}
User-controlled Reusable templates Parameterized

06 · Transport

Transport layer

MCP is transport-agnostic. The same JSON-RPC protocol runs over two very different transports. Choosing the right one depends on where your server runs.

When to use StdioServer runs locally as a subprocess. The Client spawns the Server process and communicates via stdin/stdout pipes. No network overhead. Perfect for local tools (file system, local DB, code tools).

Java Stdio server bootstrap 
import io.modelcontextprotocol.server.McpServer;
import io.modelcontextprotocol.server.McpServerFeatures;
import io.modelcontextprotocol.server.transport.StdioServerTransportProvider;

public class MyMcpServer {
    public static void main(String[] args) {

        // Use STDIO transport — communicate via stdin/stdout
        var transportProvider = new StdioServerTransportProvider();

        var server = McpServer.sync(transportProvider)
            .serverInfo("my-server", "1.0.0")
            .build();

        // Server now reads JSON-RPC from stdin, writes to stdout
        System.err.println("Server running on stdio");
    }
}

When to use HTTP+SSEServer runs remotely (different machine, container, cloud). Client sends HTTP POST requests; server pushes responses via Server-Sent Events. Allows multi-client connections.

Java HTTP+SSE server with Spring Boot 
@SpringBootApplication
public class McpServerApplication {

    @Bean
    public WebMvcSseServerTransportProvider sseTransport(ObjectMapper mapper) {
        // SSE transport provider — registers /sse and /message endpoints
        return new WebMvcSseServerTransportProvider(mapper, "/mcp/message");
    }

    @Bean
    public McpSyncServer mcpServer(WebMvcSseServerTransportProvider transport) {
        return McpServer.sync(transport)
            .serverInfo("remote-server", "1.0.0")
            .build();
    }
}
07 · Protocol

JSON-RPC protocol

MCP uses JSON-RPC 2.0 as its message format. Every message is a JSON object. There are three types of messages.

Request

Has id, method, and params. Expects a response from the other side.

Notification

Has method but no id. Fire-and-forget — no response expected.

Response

Has id matching the request. Contains either result or error.

Core MCP methods

MethodDirectionPurpose
initializeClient → ServerStart handshake, share capabilities
tools/listClient → ServerGet list of available tools
tools/callClient → ServerExecute a specific tool
resources/listClient → ServerGet available resources
resources/readClient → ServerRead a resource's content
prompts/listClient → ServerGet available prompt templates
prompts/getClient → ServerGet a specific prompt template
notifications/tools/list_changedServer → ClientTools have been updated
sampling/createMessageServer → ClientServer requests AI completion

Defining and registering a tool

Java Tool registration — file reader tool 
import io.modelcontextprotocol.server.McpServer;
import io.modelcontextprotocol.spec.McpSchema.*;

var fileReadTool = new Tool(
    "read_file",        // Tool name (AI uses this to call it)
    "Read a file from the local filesystem",
    new Schema(            // JSON Schema for input validation
        Map.of(
            "type", "object",
            "properties", Map.of(
                "path", Map.of(
                    "type", "string",
                    "description", "Absolute path to the file"
                )
            ),
            "required", List.of("path")
        )
    )
);

// Handler: receives arguments, returns result
SyncToolSpecification spec = new SyncToolSpecification(
    fileReadTool,
    (exchange, args) -> {
        String path = (String) args.get("path");
        try {
            String content = Files.readString(Path.of(path));
            return new CallToolResult(
                List.of(new TextContent(content)),
                false  // isError = false
            );
        } catch (IOException e) {
            return new CallToolResult(
                List.of(new TextContent("Error: " + e.getMessage())),
                true  // isError = true
            );
        }
    }
);

Registering a resource

Java Resource registration 
SyncResourceSpecification configResource = new SyncResourceSpecification(
    new Resource(
        "config://app/settings",       // URI
        "Application Settings",          // Name
        "Current app configuration",     // Description
        "application/json",              // MIME type
        null                             // annotations
    ),
    (exchange, request) -> {
        // Load and return the configuration JSON
        String configJson = loadAppConfig();
        return new ReadResourceResult(
            List.of(new TextResourceContents(
                request.uri(), "application/json", configJson
            ))
        );
    }
);

Building and starting the server

Java Complete server assembly 
var server = McpServer.sync(new StdioServerTransportProvider())
    .serverInfo("file-tools", "1.0.0")
    .capabilities(ServerCapabilities.builder()
        .tools(true)      // Supports tools
        .resources(true, true)  // Supports resources + subscribe
        .logging()         // Supports logging
        .build())
    .tools(spec)           // Register our file read tool
    .resources(configResource)  // Register our config resource
    .build();

// Server is now running, listening on stdin/stdout
System.err.println("MCP server started");
09 · Java Client

Building an MCP client in Java

The MCP Client connects to a Server, negotiates capabilities, and then lets you call tools and read resources programmatically.

Java Synchronous MCP client — list tools and call one 
import io.modelcontextprotocol.client.McpClient;
import io.modelcontextprotocol.client.transport.ServerParameters;
import io.modelcontextprotocol.client.transport.StdioClientTransport;
import io.modelcontextprotocol.spec.McpSchema.*;

public class McpClientExample {

    public static void main(String[] args) {

        // 1. Define how to launch the server subprocess
        var serverParams = ServerParameters.builder("java")
            .args("-jar", "my-mcp-server.jar")
            .build();

        // 2. Create transport (STDIO)
        var transport = new StdioClientTransport(serverParams);

        // 3. Create client and connect — handshake happens here
        try (var client = McpClient.sync(transport)
                .clientInfo("my-client", "1.0.0")
                .build()) {

            client.initialize();  // Runs the handshake

            // 4. List available tools
            ListToolsResult tools = client.listTools();
            System.out.println("Available tools:");
            tools.tools().forEach(t ->
                System.out.println("  - " + t.name() + ": " + t.description())
            );

            // 5. Call a specific tool
            CallToolResult result = client.callTool(
                new CallToolRequest(
                    "read_file",
                    Map.of("path", "/tmp/hello.txt")
                )
            );

            // 6. Process result
            result.content().forEach(content -> {
                if (content instanceof TextContent text) {
                    System.out.println("File content: " + text.text());
                }
            });
        }  // auto-closes — sends disconnect
    }
}

Listing and reading resources

Java Resource operations 
// List all resources the server exposes
ListResourcesResult resources = client.listResources();

// Read a specific resource by URI
ReadResourceResult config = client.readResource(
    new ReadResourceRequest("config://app/settings")
);

config.contents().forEach(c -> {
    if (c instanceof TextResourceContents text) {
        System.out.println("Config: " + text.text());

10 · Full Example

Full working example

A complete Java MCP server that exposes a database query tool, a file reader tool, and a configuration resource — with full error handling.

Java ProductDatabaseMcpServer.java — production-ready 
package com.example.mcp;

import io.modelcontextprotocol.server.*;
import io.modelcontextprotocol.server.transport.StdioServerTransportProvider;
import io.modelcontextprotocol.spec.McpSchema.*;
import java.sql.*;
import java.util.*;

public class ProductDatabaseMcpServer {

    private static final String DB_URL = "jdbc:postgresql://localhost/products";

    public static void main(String[] args) throws Exception {

        // ── Tool: search products ──────────────────────────────
        var searchTool = new Tool(
            "search_products",
            "Search the product catalog by name or category",
            buildSearchSchema()
        );

        SyncToolSpecification searchSpec = new SyncToolSpecification(
            searchTool,
            (exchange, args_) -> {
                String query  = (String) args_.getOrDefault("query", "");
                Integer limit = (Integer) args_.getOrDefault("limit", 10);

                try (Connection conn = DriverManager.getConnection(DB_URL);
                     PreparedStatement ps = conn.prepareStatement(
                         "SELECT id, name, price, stock FROM products " +
                         "WHERE name ILIKE ? LIMIT ?")) {

                    ps.setString(1, "%" + query + "%");
                    ps.setInt(2, limit);

                    ResultSet rs = ps.executeQuery();
                    StringBuilder sb = new StringBuilder();
                    int count = 0;

                    while (rs.next()) {
                        sb.append(String.format(
                            "ID: %d | %s | $%.2f | Stock: %d\n",
                            rs.getInt("id"),
                            rs.getString("name"),
                            rs.getDouble("price"),
                            rs.getInt("stock")
                        ));
                        count++;
                    }

                    String result = count == 0
                        ? "No products found for: " + query
                        : sb.toString();

                    return new CallToolResult(
                        List.of(new TextContent(result)), false
                    );

                } catch (SQLException e) {
                    return new CallToolResult(
                        List.of(new TextContent("DB error: " + e.getMessage())),
                        true  // isError = true
                    );
                }
            }
        );

        // ── Tool: get product by ID ────────────────────────────
        var getByIdTool = new Tool(
            "get_product",
            "Get full details for a product by its ID",
            buildGetByIdSchema()
        );

        SyncToolSpecification getByIdSpec = new SyncToolSpecification(
            getByIdTool,
            (exchange, args_) -> {
                int id = ((Number) args_.get("id")).intValue();
                try (Connection conn = DriverManager.getConnection(DB_URL);
                     PreparedStatement ps = conn.prepareStatement(
                         "SELECT * FROM products WHERE id = ?")) {
                    ps.setInt(1, id);
                    ResultSet rs = ps.executeQuery();
                    if (rs.next()) {
                        String json = String.format(
                            """
                            {
                              "id": %d,
                              "name": "%s",
                              "price": %.2f,
                              "stock": %d,
                              "description": "%s"
                            }""",
                            rs.getInt("id"), rs.getString("name"),
                            rs.getDouble("price"), rs.getInt("stock"),
                            rs.getString("description")
                        );
                        return new CallToolResult(
                            List.of(new TextContent(json)), false);
                    }
                    return new CallToolResult(
                        List.of(new TextContent("Product not found: " + id)), true);
                } catch (SQLException e) {
                    return new CallToolResult(
                        List.of(new TextContent("DB error: " + e.getMessage())), true);
                }
            }
        );

        // ── Resource: database stats ───────────────────────────
        SyncResourceSpecification statsResource = new SyncResourceSpecification(
            new Resource("db://stats", "Database Stats",
                         "Live product count and inventory stats",
                         "application/json", null),
            (exchange, req) -> {
                try (Connection conn = DriverManager.getConnection(DB_URL);
                     Statement stmt = conn.createStatement()) {
                    ResultSet rs = stmt.executeQuery(
                        "SELECT COUNT(*) as total, SUM(stock) as stock FROM products");
                    rs.next();
                    String json = """
                        {"total_products": %d, "total_stock": %d}"""
                        .formatted(rs.getInt("total"), rs.getLong("stock"));
                    return new ReadResourceResult(List.of(
                        new TextResourceContents(req.uri(), "application/json", json)));
                } catch (SQLException e) {
                    throw new RuntimeException(e);
                }
            }
        );

        // ── Assemble and start the server ─────────────────────
        var server = McpServer.sync(new StdioServerTransportProvider())
            .serverInfo("product-db", "1.0.0")
            .capabilities(ServerCapabilities.builder()
                .tools(true)
                .resources(true, false)
                .logging()
                .build())
            .tools(searchSpec, getByIdSpec)
            .resources(statsResource)
            .build();

        System.err.println("ProductDB MCP Server started on stdio");
    }

    private static Schema buildSearchSchema() {
        return new Schema(Map.of(
            "type", "object",
            "properties", Map.of(
                "query", Map.of("type", "string", "description", "Search term"),
                "limit", Map.of("type", "integer", "default", 10)
            ),
            "required", List.of("query")
        ));
    }

    private static Schema buildGetByIdSchema() {
        return new Schema(Map.of(
            "type", "object",
            "properties", Map.of(
                "id", Map.of("type", "integer", "description", "Product ID")
            ),
            "required", List.of("id")
        ));
    }
}
11 · Security

Security model

MCP has a layered security model. Understanding it is essential before exposing any real-world data through an MCP server.

🛡️

Tool approval

Hosts can require user approval before executing any tool call. The AI proposes the call; the user confirms it.

🔒

No key exposure

API keys and secrets live inside the MCP server process. The AI never sees them — only the tool's results.

📋

Capability scoping

Servers declare only what they support. A read-only server declares no tool capabilities — writes are impossible.

🔍

Audit logging

The logging capability lets servers stream structured logs to the host for full audit trails.

Input validation in Java

Java Always validate tool inputs — never trust the AI blindly 
SyncToolSpecification safeSpec = new SyncToolSpecification(
    deleteFileTool,
    (exchange, args) -> {
        String path = (String) args.get("path");

        // 1. Validate input is present
        if (path == null || path.isBlank()) {
            return error("path is required");
        }

        // 2. Prevent path traversal attacks
        Path resolved = Path.of("/allowed/base").resolve(path).normalize();
        if (!resolved.startsWith("/allowed/base")) {
            return error("Path traversal not allowed");
        }

        // 3. Check file exists before acting
        if (!Files.exists(resolved)) {
            return error("File not found: " + path);
        }

        // 4. Log the action for audit trail
        exchange.loggingNotification(LoggingMessageNotification.builder()
            .level(LoggingLevel.WARNING)
            .data("Deleting file: " + resolved)
            .build());

        Files.delete(resolved);
        return success("Deleted: " + path);
    }
);

Prompt injection riskMalicious content in files or databases can attempt to hijack the AI's behaviour. Always sanitise content before returning it as a tool result — especially when the AI will act on the output.

MCP vs alternatives

How does MCP compare to other approaches for giving AI models access to external tools and data?

FeatureMCPFunction CallingLangChain ToolsCustom APIs
Standardised protocol✅ Yes❌ Per-model❌ Framework-specific❌ Bespoke
Works across AI models✅ Yes❌ Vendor lock-in⚠️ With adapters✅ Yes
Bidirectional comms✅ Yes❌ No❌ No⚠️ Webhooks

Bottom lineMCP wins when you want portability — build once, use with any MCP-compatible AI. Function calling wins when you need tight vendor-specific control. Use LangChain when you're already in that ecosystem and don't need cross-model support.

When to choose MCP

✅

Use MCP when...

You want tools reusable across Claude, GPT, and others. You need real-time server-to-client push. You want a standard audit and approval flow.

⚠️

Consider alternatives when...

You're locked to one AI provider. Performance is critical and you need zero protocol overhead. You have an existing tool system that works well.
