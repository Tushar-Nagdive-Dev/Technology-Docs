🧠 What is teeing() ?

Collectors.teeing(downstream1, downstream2, merger) combines two collectors into one. The stream is traversed once, each element is fed to both downstream collectors simultaneously. After processing all elements, the merger function combines the two results.

// signature public static <T, R1, R2, R> Collector<T, ?, R> teeing( Collector<? super T, ?, R1> downstream1, Collector<? super T, ?, R2> downstream2, BiFunction<? super R1, ? super R2, R> merger )

⚙️ Internal mechanics

  • ✔ Two separate accumulators (one per collector)
  • ✔ Each element → both accumulators (single iteration)
  • ✔ Final step: merger(R1, R2) → R
  • ✔ Works in parallel streams (if downstream collectors are concurrent)

🏭 Production superpowers

  • 🚀 One-pass reports – total + average, min + max, count + distinct
  • 📁 Non-rewindable sources (files, network, Kafka streams) – process once
  • 🧪 Validation rules e.g., sum of squares vs square of sum
  • ⚡ Parallel efficiency – combine complex aggregations in accurate way
  • 🧩 Nested teeing for three or more metrics

📈 Use case: Report generation

Imagine processing transactions from a log file: you need total amount and max transaction value for fraud checks, without scanning twice. teeing() makes it trivial:

// Java real example record Transaction(double amount, String id) {} var stats = transactions.stream().collect(teeing( summingDouble(Transaction::amount), maxBy(Comparator.comparingDouble(Transaction::amount)), (total, maxTx) -> new Report(total, maxTx.orElse(null)) ));
✨ Why better? Avoids second stream scan -> less I/O, deterministic for infinite or non-replayable streams.

🧬 Nested teeing (3+ metrics)

You can nest teeing() to handle three aggregates in one go. For example: sum, count, product of elements.

// three metrics using nesting var result = numbers.stream().collect(teeing( summingInt(i -> i), teeing( counting(), reducing(1, (a,b) -> a * b), (cnt, prod) -> new Pair(cnt, prod) ), (sum, pair) -> new Triple(sum, pair.cnt, pair.prod) ));

⚡ Parallel streams ready

Both downstream collectors can benefit from fork-join pool when using .parallelStream(). Single teeing collector shares the stream spliterator without double parallel overhead.

🔍 Best practices & caveats in production

✅ Perfect for:
  • statistical summaries (avg, sum, min, max, count)
  • validation rules across one dataset
  • enriching DTOs with derived fields
⚠️ Watch out:
  • Avoid stateful collectors with side-effects
  • Merger runs once – don't modify external state
  • For many aggregations (>3), consider custom collector or record
