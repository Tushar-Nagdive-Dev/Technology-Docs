ArrayList Deep Dive

ArrayList is the most commonly used List implementation in Java. Internally it uses a dynamic array.

✅ Best Use Cases

  • Read-heavy applications
  • Fast random access
  • Pagination systems
  • Analytics dashboards
  • Product catalog systems

❌ Common Mistakes

  • Frequent middle insertion
  • Frequent beginning deletion
  • Ignoring initial capacity
  • Using synchronized access incorrectly

Internal Working

Index: 0 1 2 3 A B C D Underlying Structure: Object[] elementData
Important: When ArrayList becomes full, Java creates a new larger array and copies all old elements.
ArrayListExample.java 

import java.util.ArrayList;
import java.util.List;

public class ArrayListExample {

    public static void main(String[] args) {

        List products = new ArrayList<>(1000);

        products.add("Laptop");
        products.add("Mouse");
        products.add("Keyboard");

        System.out.println(products.get(0));

        for(String product : products){
            System.out.println(product);
        }
    }
}

LinkedList Deep Dive

LinkedList uses a doubly linked node structure where each node stores previous and next node references.

[Prev|A|Next] <-> [Prev|B|Next] <-> [Prev|C|Next]

✅ Best Use Cases

  • Frequent insertion/deletion
  • Music queues
  • Undo/Redo systems
  • Browser navigation

❌ Problems

  • Slow random access
  • Consumes more memory
  • Traversal is expensive
LinkedListExample.java 

import java.util.LinkedList;

public class LinkedListExample {

    public static void main(String[] args) {

        LinkedList queue = new LinkedList<>();

        queue.add("Song 1");
        queue.add("Song 2");

        queue.addFirst("Priority Song");

        System.out.println(queue);
    }
}

HashMap Deep Dive

HashMap stores data using key-value pairs and hashing algorithms.

Key → hashCode() → Bucket Index Bucket 0 → Node Bucket 1 → Empty Bucket 2 → Node → Node Bucket 3 → TreeNode

✅ Real World Use Cases

  • Caching
  • Session management
  • API response storage
  • Configuration systems
  • Database indexing

❌ Common Mistakes

  • Mutable keys
  • Bad hashCode implementation
  • Ignoring collisions
  • Using HashMap in multithreading
Java 8 Optimization: Large collision chains automatically convert into Red-Black Trees.
HashMapExample.java 

import java.util.HashMap;
import java.util.Map;

public class HashMapExample {

    public static void main(String[] args) {

        Map users = new HashMap<>();

        users.put(101, "Tushar");
        users.put(102, "Rahul");

        System.out.println(users.get(101));
    }
}

TreeSet Deep Dive

TreeSet automatically stores unique elements in sorted order using a Red-Black Tree.

50 / \ 30 70 / \ / \ 20 40 60 80

✅ Best Use Cases

  • Leaderboards
  • Ranking systems
  • Sorted unique records
  • Financial systems

⚠ Important

  • Slower than HashSet
  • Uses sorting internally
  • Operations are O(log n)
TreeSetExample.java 

import java.util.TreeSet;

public class TreeSetExample {

    public static void main(String[] args) {

        TreeSet names = new TreeSet<>();

        names.add("Zack");
        names.add("Alice");
        names.add("Bob");

        System.out.println(names);
    }
}

Concurrent Collections

ConcurrentHashMap

Thread-safe version of HashMap optimized for concurrent applications.

CopyOnWriteArrayList

Excellent for read-heavy multi-threaded systems.

Fail Fast vs Fail Safe

Fail Fast

Throws ConcurrentModificationException when collection changes during iteration.

Fail Safe

Works on cloned collection and avoids modification exceptions.

Most Important Interview Questions

Why HashMap is O(1)?

Because hashing directly calculates bucket location.

ArrayList vs LinkedList?

ArrayList is better for reads, LinkedList for insertions/deletions.

Why equals() and hashCode() matter?

They control uniqueness and bucket placement in hashing collections.
