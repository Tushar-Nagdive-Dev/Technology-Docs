Answer a few questions to find the exact Java Collection you need.

Do you need to store Key-Value pairs? (e.g., UserID -> UserObject)

Use: HashMap

O(1) lookup time. The absolute best choice for key-value pairings when order doesn't matter.

ArrayList

The default, go-to collection. It uses a dynamic array under the hood.

✅ When to use

  • Read-heavy applications.
  • When you need fast random access by index list.get(5) (O(1) time).
  • When you mostly add elements to the end of the list.
Real-time Example: An e-commerce product catalog page where users scroll and read items, but rarely insert items into the exact middle of the list.

❌ When NOT to use

  • When you are doing massive amounts of inserts/deletes in the middle of the list.
  • Why? Because if you insert at index 0, ArrayList has to shift every single subsequent element one spot to the right (O(n) time).
Pro Tip (Sizing): ArrayList starts with a capacity of 10. When it fills up, it creates a new array 1.5x larger and copies the old data over. If you know you are adding 10,000 items, do new ArrayList<>(10000). You just saved the CPU from doing dozens of costly array copy operations!
import java.util.ArrayList; import java.util.List; List<String> catalog = new ArrayList<>(500); // Pre-sized! catalog.add("Laptop"); catalog.add("Mouse"); String item = catalog.get(0); // Lightning fast O(1) read

LinkedList

Uses a Doubly-Linked List under the hood. Elements (nodes) point to the previous and next elements.

✅ When to use

  • Write-heavy applications.
  • When you are constantly adding or removing elements from the beginning or middle of the collection.
  • It just changes two pointers to insert an item (O(1) time, assuming you are already at the position via Iterator).
Real-time Example: A Music Player Queue. You frequently drag and drop songs to the top or middle of the "Up Next" list, or delete songs from the queue.

❌ When NOT to use

  • When you need random access!
  • If you call list.get(5000), LinkedList has to start at 0 and traverse link-by-link 5,000 times to find it (O(n) time).
  • It consumes more memory than ArrayList (because it stores pointers).

HashSet & LinkedHashSet

Sets guarantee uniqueness. No duplicates allowed. Powered by a HashMap under the hood.

1. HashSet

✅ When to use

When you just need a bucket of unique items and you absolutely do not care about the order they are in. Blazing fast O(1) add and contains.

Example: Storing the unique IP addresses of visitors who hit your website today.

❌ When NOT to use

When you need to iterate through the items in a specific order, or you need to sort them.

2. LinkedHashSet

✅ When to use

When you need uniqueness, BUT you want to preserve the Insertion Order. Slower than HashSet, but keeps order.

Example: A user selects categories for their blog post ("Tech", "Java", "Coding"). You want unique tags, but you want to display them in the exact order the user clicked them.
Pro Tip (Equals & HashCode): If you put custom objects (like a User class) into a Set, you MUST override equals() and hashCode(). If you don't, Java looks at the memory address, and will allow two users with the exact same ID into the Set!

TreeSet

A Set that guarantees uniqueness AND is automatically sorted. Powered by a Red-Black Tree.

✅ When to use

  • When you need a continuously sorted collection of unique items without manually calling Collections.sort().
  • Provides useful methods like higher(), lower(), first(), and last().
Real-time Example: A live Gaming Leaderboard. As unique player scores update, the TreeSet automatically keeps them perfectly sorted from highest to lowest.

❌ When NOT to use

  • When speed is your #1 priority. Inserts and lookups are O(log n) because it has to traverse the tree structure. HashSet (O(1)) is much faster.
import java.util.TreeSet; // Automatically sorts alphabetically TreeSet<String> names = new TreeSet<>(); names.add("Zack"); names.add("Alice"); names.add("Bob"); System.out.println(names); // Outputs: [Alice, Bob, Zack]

HashMap & LinkedHashMap

Stores data in Key-Value pairs. Keys must be unique. Values can be duplicates.

✅ HashMap (The King)

The most used collection in Java. Extremely fast O(1) lookups by Key. Order is not guaranteed.

Example: Caching user profiles. Key = "user_101", Value = UserProfileObject. You instantly fetch the profile without searching a list.

✅ LinkedHashMap

Like HashMap, but maintains Insertion Order. Also has a special feature to maintain "Access Order".

Example: Building an LRU (Least Recently Used) Cache. It can automatically delete the oldest accessed keys to save memory!
Pro Tip (Load Factor & Collisions): HashMap works by hashing keys into "buckets". By default, when the map is 75% full (Load Factor 0.75), it doubles its buckets to avoid "collisions" (two keys hashing to the same bucket). If a bucket gets too many collisions, Java 8 secretly upgrades that bucket from a Linked List to a Red-Black tree to maintain speed!

TreeMap

Key-Value pairs, but the keys are automatically sorted.

✅ When to use

  • When you need a Map, but you also need to iterate over the keys in sorted order.
  • When you need range queries on keys (e.g., "Give me all entries between Key A and Key Z").
Real-time Example: A Financial Ledger or Stock Ticker. Key = Timestamp, Value = Transaction Details. You can easily query map.subMap(startTime, endTime) to get all transactions in a specific hour.

PriorityQueue & ArrayDeque

1. PriorityQueue

✅ When to use

When items need to be processed based on their Priority, not when they arrived. Elements are sorted as they enter.

Example: A Hospital Triage System. Patients arrive (added to queue). A patient with a heart attack is given higher priority and jumps to the front of the queue ahead of a patient with a cold.

2. ArrayDeque (Pronounced "Deck")

✅ When to use

A Double-Ended Queue. You can add/remove from both the front AND the back instantly.

Example: Browser Back/Forward history. You push new pages to the top, pop them to go back.
Pro Tip (The Death of Stack): Never use the legacy Stack class. It is synchronized and terribly slow. If you need LIFO (Last-In-First-Out) stack behavior, the official Java recommendation is to use ArrayDeque (e.g., Deque<String> stack = new ArrayDeque<>(); stack.push(); stack.pop();).
