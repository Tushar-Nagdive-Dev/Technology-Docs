Types of Bulkheads in Resilience4j

1. Semaphore Bulkhead

Uses a mathematical counter (a semaphore) to limit concurrent requests.

  • How it works: If limit is 5, it hands out 5 "tickets". The 6th request must wait for a ticket or fail.
  • Pros: Very lightweight. No extra threads are created. Works well across different threading models (like WebFlux).
  • Cons: Cannot strictly timeout a thread that is already running inside the bulkhead.

2. Thread Pool Bulkhead

Uses a fixed, dedicated pool of threads and a waiting queue.

  • How it works: Assigns a completely separate thread pool (e.g., 5 threads) strictly for this service.
  • Pros: Offers strict isolation. If the remote service hangs, it only hangs the dedicated thread, not the main Tomcat request thread.
  • Cons: Heavier on system resources due to context switching between thread pools.
